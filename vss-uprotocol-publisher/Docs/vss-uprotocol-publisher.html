VSS uProtocol Publisher

The bridge between the AZ3166 and the Guardian. From each MQTT reading it maps temperature_degC to one VSS signal and publishes it as a uProtocol message. The board's counter is not part of VSS: it travels in the same message as an extra field, and the publisher derives seq from it. The publisher translates and does not judge: implausible values pass through so the Guardian can detect them.

From counter to seq

The board sends one message per second; its counter runs 0 to 255 and starts again at 0. The publisher does not copy it into seq; it advances its own seq whenever the counter changes and keeps it when the counter repeats. A repeat is how the Guardian tells a re-delivered or frozen reading from fresh data.

Current limits

The sample time is when the publisher created the uMessage (its UUIDv7 id), so delay between the board and the broker is invisible. The Guardian's latency check only covers publisher to Guardian.

Readings that MQTT delivers back to back after a Wi-Fi hiccup are turned into uMessages milliseconds apart, so their sample times are too. A 0.1 °C step between them can trip the Guardian's spike check.

seq advances by one per counter change, so skipped counter values (lost readings) are not counted as missing in the Guardian's heartbeat.
