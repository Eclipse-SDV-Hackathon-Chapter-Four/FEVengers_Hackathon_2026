Guardian State Machine

How the Guardian moves between its six states, and what happens inside it for every temperature sample and every supervision tick. Numbers are the defaults from config/guardian.toml; config/demo.toml shortens the stuck window to 5 s and the mitigation timeout to 10 s.

CRITICAL→MITIGATING Immediately, in the same step Starts the 30 s mitigation timer
MITIGATING→MONITORING Temperature < 62 °C held for 5 s Releases all active mitigations
MITIGATING→CRITICAL 30 s after the request and the temperature is not below 62 °C; also checked on ticks, so it fires without samples Requests OccupantEvacuationWarning (level 2), again on every further timeout

Timers: tick and heartbeat

All events of one step are numbered by a single Guardian-wide seq. Zenoh does not keep the order between the state, fault and mitigation topics, so consumers sort by seq.

Fault events carry the DFM catalog id in catalog_id (for example btg.temp.stuck). Transport faults are Guardian-internal and carry null.
